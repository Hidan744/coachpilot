# CoachPilot AI — отчёт о доработке (октябрь 2026)

## 1. Аудит исходного проекта

Полный аудит — `docs/AUDIT.md`. Коротко: у проекта был рабочий фундамент. Это Flutter-клиент для Android, iOS, Windows и веба, сервер FastAPI + PostgreSQL и синхронизация, которая работает без сети. Уже были каталог, конструктор, календарь, ОФП, статистика, Live-матч и ссылка родителям.

Основные пробелы:
- конструктор не учитывал историю команды;
- у рекомендаций не было решения тренера и уверенности;
- не было видеоразбора;
- не было школ, ролей, кабинетов семьи, тарифов, уведомлений и журнала действий;
- данные несовершеннолетних защищались слабо.

## 2. Что реализовано

**Ядро (этап C)**
- **Конструктор:**
  - учёт истории: не повторять упражнения последних занятий, интенсивность по RPE и ближайшему матчу, приоритеты из отчётов, разбора матча, целей сезона и программ игроков;
  - выбор «кто будет» (травмированные исключены) и учёт размера площадки;
  - «Изменились условия» — пересобираются только неподходящие блоки, длительность пересчитывается точно;
  - план Б на плохую погоду или мини-площадку, вариант «если игроков меньше», переходы между блоками;
  - всё это попадает в PDF.
- **Рекомендации «план → факт»:**
  - у каждой рекомендации есть наблюдение, данные, действие, ожидаемая цель, уверенность и ограничения;
  - новые правила: пропуски игрока, систематический выход за план, часто пропускаемая часть, тема, которая повторяется в отчётах, достигнутая цель;
  - тренер принимает, изменяет или отклоняет рекомендацию; решение синхронизируется;
  - после занятия — сводка «что произошло / что это означает / что делать / на чём сосредоточиться».
- **Методическая библиотека:**
  - у упражнения есть типичные ошибки, источник, права, ссылка на видео и теги;
  - честные статусы «не заполнено» и «права не указаны» (у импортированных упражнений);
  - копия сохраняет происхождение.
- **Развитие игрока:**
  - цели по видам (техника, тактика, физика, психология) со сроком 4/8/12 недель, контрольными замерами, динамикой и пометкой «срок прошёл»;
  - история изменений профиля;
  - вкладка «История» — единая хронология, у каждого события указан источник: измерение, оценка тренера или автоматический учёт.

**Матчи и тактика (этап E)**
- Разбор матча: итоги, выводы, задачи на тренировку (они же становятся приоритетами конструктора), заметки по игрокам.
- Видеоразбор, первый этап:
  - ссылка на видео и эпизоды по таймкоду с тегом, игроками, комментарием и схемой;
  - обратная связь отдельному игроку копируется текстом;
  - автоматического распознавания нет.
- Тактическая доска: экспорт в PNG и PDF, привязка к тренировке.

**Российский запуск (этап D)**
- Тарифы Free / Pro / Academy: цены в рублях и лимиты AI заданы только в настройках сервера. Оплата не имитируется, тестовый режим запрещён в production.
- Экран статусов интеграций: AI, Telegram, оплата, почта.
- Telegram:
  - привязка по одноразовому коду, тестовое сообщение;
  - напоминания тренеру и родителям за сутки (запуск по расписанию, без повторов);
  - без токена ничего не отправляется.
- Журнал действий, согласие родителя (без него сервер не создаёт ссылку или код для несовершеннолетнего), сроки хранения (`app.maintenance purge`).
- Тип команды (детская, юношеская, любительская, академия, индивидуальный тренер) включает и выключает разделы.
- Главная: ближайший матч, приоритеты команды, подтверждения участия.
- Документы: `SECURITY.md` (152-ФЗ, вопросы юристу) и `DEPLOY_RU.md` (инфраструктура в России).

**Школа и роли (этап E)**
- Регистрация как тренер, родитель или игрок.
- Кабинет семьи: подключение по коду, расписание, подтверждение участия, открытые тренером материалы.
- Футбольная школа:
  - роли «владелец / администратор / старший тренер / тренер»;
  - приглашения по коду;
  - сводка по командам за 28 дней с выгрузкой в CSV;
  - передача команды со всеми данными: у прежнего тренера записи исчезают при синхронизации.
- Изоляция школ и семей проверяется на сервере и покрыта тестами.

## 4. Как запустить

```
# сервер
cd backend && pip install -r requirements-dev.txt
alembic upgrade head && python -m app.catalog.seed
uvicorn app.main:app --port 8000

# приложение
cd app && flutter pub get
flutter run                                   # телефон/Windows
flutter build web --no-web-resources-cdn --dart-define=API_URL=http://localhost:8000

# демо без сервера
flutter build web --no-web-resources-cdn --dart-define=DEMO_ONLY=true --dart-define=DEMO_SAMPLE=true
```

Продовые переменные окружения перечислены в `docs/DEPLOY_RU.md`.

## 6. Интеграции

| Интеграция | Состояние |
|---|---|
| AI (YandexGPT, GigaChat, OpenAI-совместимые) | Код есть; в тестах подставная модель. Нужен ключ — без него планы собираются по правилам |
| Telegram | Код и тесты с подменой канала; не подключён — нужен бот, токен и webhook |
| Оплата | Не подключена; тестовый режим без денег. Нужен провайдер (ЮKassa, CloudPayments) |
| Почта | Не подключена |
| Видео | Только ссылки; хранилища и загрузки нет |

## 7. Известные проблемы и ограничения

- Видеоразбор ручной: нет загрузки файла и проигрывателя с переходом к таймкоду; ссылка открывается снаружи.
- Тактическая доска: анимация не экспортируется в видео (честно не предлагается).
- Уведомления о переносе времени тренировки не отправляются — только напоминания за сутки.
- Опрос самочувствия перед занятием и сбор RPE от игроков через Telegram не сделаны.
- Возрастные группы заданы в коде (U6–U19, взрослые), а не в справочнике.
- Импорт игроков отмечает дубликаты, но не показывает построчный отчёт об ошибках.
- Тарифные лимиты, кроме квоты AI (число команд, тренеров), не применяются.
- В школе руководитель видит сводку, но не карточки детей. Общей библиотеки школы и шаблонов тренировок по возрастам ещё нет.
- Интерфейс только на русском: строки не вынесены в файлы локализации.

## 9. Готовность к пилоту

Готов к пилоту с одной командой на собственном сервере.

Что для этого уже есть:
- ключевые сценарии тренера проверены автоматически;
- данные изолированы;
- офлайн-режим работает;
- экспорт формирует настоящие файлы;
- есть резервная копия;
- у интеграций проверяемый статус.

Для коммерческого запуска не хватает:
- юридической проверки;
- развёртывания в России;
- подключения оплаты и AI-ключа;
- проверки на реальных телефонах;
- нагрузочного теста.

## 10. Что требует внешних ключей, инфраструктуры или юриста

- **Ключи:** AI-провайдер, бот Telegram, платёжный провайдер, почтовый сервис.
- **Инфраструктура:** сервер и PostgreSQL в России, HTTPS-домен, хранилище копий и видео, cron для напоминаний и очистки, сбор логов, менеджер секретов.
- **Юрист:** оператор ПД и договор поручения, форма согласия законных представителей (до 14 и 14–18 лет), уведомление Роскомнадзора, статус отметок «травма» и тестов ОФП, сроки хранения, передача обезличенных текстов в AI, политика конфиденциальности и оферта (подробно — `docs/SECURITY.md`).
