## P1 — ошибки, исправить в первую очередь

### [x] 1. Месячный лимит AI сбрасывается только при генерации плана

**Проблема.** Сброс счётчика `ai_used` в начале нового месяца есть только в `_quota_ok`
(`backend/app/ai/planner.py`). В `backend/app/ai/report.py` (`structure_report`) и
`backend/app/ai/drills_import.py` (`parse_drills`) проверка `sub.ai_used >= sub.ai_quota_month`
идёт без сброса. Тренер, исчерпавший лимит в прошлом месяце, не может пользоваться AI-отчётом
и AI-импортом упражнений, пока не сгенерирует план.

**Что сделать.**
- Вынести `_quota_ok` в общий модуль (например, `backend/app/ai/quota.py`) как `quota_ok(db, owner_id)`.
- Использовать её во всех трёх местах: планы, отчёт, импорт упражнений.

**Проверка.** Тест в `backend/tests/test_ai.py`: подписка с `period_start` в прошлом месяце и
`ai_used == ai_quota_month` → `/ai/report` и `/ai/drills/parse` возвращают `source == "ai"`,
а `ai_used` после вызова равен 1.

### [x] 2. Блокировка входа чужого аккаунта (лимит попыток считается только по email)

**Проблема.** API запускается с `uvicorn --proxy-headers` (`backend/Dockerfile`), но uvicorn
доверяет заголовкам `X-Forwarded-For` только от `127.0.0.1`. Caddy работает в отдельном
контейнере, поэтому `request.client.host` — всегда IP Caddy. Ключ лимита в
`backend/app/routers/auth.py` (`login`) фактически равен только email: 8 неверных паролей
с любого адреса блокируют вход тренеру на 5 минут, и это можно повторять бесконечно.

Дополнительно в `backend/app/ratelimit.py`:
- при более чем 50 000 ключей вызывается `self._hits.clear()` — атакующий может нарочно
  сбросить все счётчики;
- счётчики в памяти процесса, при нескольких воркерах лимит не работает.

**Что сделать.**
- В `CMD` Dockerfile добавить `--forwarded-allow-ips` с адресом/подсетью Caddy
  (или переменную окружения `FORWARDED_ALLOW_IPS` в `deploy/docker-compose.prod.yml`).
- Разделить лимиты: по IP (строже, защищает от перебора) и по email (мягче и короче,
  чтобы чужой человек не мог надолго заблокировать тренера).
- Вместо `clear()` удалять только устаревшие ключи (у которых последняя попытка старше окна).
- Записать в `docs/DEPLOY.md`: при нескольких воркерах нужен Redis.

**Проверка.** Тест на `RateLimiter`: переполнение не сбрасывает активные ключи. Тест на `/auth/login`:
попытки с одного IP на разные email упираются в IP-лимит.

### [x] 3. Приложение выкидывает из аккаунта при одновременном обновлении токена

**Проблема.** Refresh-токен одноразовый (сервер отзывает его при обновлении). В
`app/lib/sync/api_client.dart` метод `_tryRefresh` не защищён от параллельных вызовов:
если два запроса одновременно получили 401 (типично после сворачивания приложения дольше
30 минут), оба отправляют один и тот же refresh-токен. Второй получает 401 →
`clearTokens()` → пользователь разлогинен.

**Что сделать.**
- Хранить текущее обновление в поле `Future<bool>? _refreshing`. Если оно уже идёт —
  ждать его, а не начинать новое; по завершении обнулять.
- Учесть случай, когда токен уже обновлён другим запросом: перед повтором запроса
  брать актуальный access-токен из хранилища.

**Проверка.** Тест с `MockClient`: два параллельных запроса получают 401, а `/auth/refresh` вызывается ровно
один раз, оба запроса успешно повторяются, токены не стёрты.

## P2 — желательно исправить

### [x] 4. Строка подписки заблокирована во время запроса к AI

Во всех трёх AI-эндпоинтах `db.get(Subscription, ..., with_for_update=True)` держит блокировку
строки и соединение с БД на всё время вызова LLM (до 2×60 с у плана с повторной попыткой).
Сделать так: зарезервировать лимит (`ai_used += 1`) и закоммитить, вызвать LLM без блокировки,
при ошибке вернуть резерв отдельной транзакцией. Удобно сделать вместе с задачей 1.

### [x] 5. Регистрация без ограничения частоты

`/auth/register` (`backend/app/routers/auth.py`) не ограничен и по ответу 409 показывает,
что email уже зарегистрирован. Добавить лимит по IP (тот же `RateLimiter`).

### [ ] 6. CORS `*` по умолчанию

`backend/app/config.py`: `cors_origins = ["*"]`. В `backend/app/main.py` рядом с проверкой
`jwt_secret` добавить: при `env == "prod"` и `"*"` в `cors_origins` — `RuntimeError`.

### [ ] 7. Описание страницы родителям не совпадает с поведением

В `backend/app/routers/shares.py` docstring говорит, что на страницу попадает только отмеченное
«видно родителям». На деле флаг `shared` есть только у сообщений и планов развития; посещаемость,
оценки навыков, статистика матчей и названия занятий видны всегда. Спросить владельца проекта,
что задумано: либо поправить docstring, либо добавить настройки видимости.
**Не менять поведение без подтверждения.**
