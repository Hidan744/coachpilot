# Аудит CoachPilot AI (октябрь 2026)

Состояние проверено по исходному коду (Flutter-приложение `app/`, сервер FastAPI `backend/`),
автотестам (164 теста приложения, 76 тестов сервера, 8 сценариев в браузере) и демо-сборке.
Собранный HTML — это сборка из `app/`; правки вносятся только в исходный код.

## Стек и архитектура

- Клиент: Flutter (Android, iOS, Windows, веб), Riverpod, go_router.
- Локальное хранение: SQLite (drift), записи в JSON + очередь изменений (outbox).
- Сервер: FastAPI + SQLAlchemy + PostgreSQL, миграции alembic.
- Синхронизация: `/sync/push`, `/sync/pull`, порядковый номер изменений, конфликты для тренировок, отчётов, упражнений.
- AI: `/ai/plan`, `/ai/report`, `/ai/drills/parse`, `/ai/quota` — только на сервере, ключ в переменных окружения.
- Изоляция данных: каждая запись принадлежит одному пользователю (`owner_id`), сервер проверяет владельца и ссылки.

## Работает частично

- Конструктор не учитывает историю: прошлые упражнения, нагрузку, приоритеты команды.
- Нет размера площадки, наличия ворот и выбора конкретных игроков.
- Нет пересборки только затронутых блоков при смене параметров.
- План не «готов к проведению»: нет переходов между упражнениями, варианта при нехватке игроков и плана Б на плохую погоду.
- Рекомендации нельзя принять или отклонить. Нет «ожидаемой цели» и «степени уверенности». Нет правил по пропускам игрока, систематическому выходу за план, затянувшемуся приоритету и достигнутой цели.
- В упражнениях нет типичных ошибок, источника и прав, статуса видео.
- Цели игрока не делятся на технические, тактические и физические. Нет единой хронологии игрока и истории изменений.
- В матче нет выводов тренера и задач на тренировку. Видеоразбора нет.
- Тактическая доска не экспортирует PNG и не привязывается к тренировке.
- Тариф хранится одним полем `plan`. Цен и описания тарифов нет.
- Роли штаба (`StaffMember`) — только записи, не отдельные аккаунты.

## Отсутствует

- Организации (школы), несколько тренеров с общими данными, передача команды.
- Аккаунты игрока и родителя, подтверждение участия.
- Telegram и другие уведомления.
- Оплата.
- Журнал важных действий (аудит), сроки хранения, согласия родителей.
- Профиль типа команды (детская, юношеская, любительская, академия, индивидуальный тренер).

## Риски

1. Изоляция «один владелец» не подходит для школы. Переход к организациям требует изменить модель доступа на сервере и в синхронизации.
2. Данные детей: нет согласий, журнала доступа и сроков хранения. Перед коммерческим запуском нужна юридическая проверка по 152-ФЗ.
3. Ссылка для родителей — это токен без входа: кто получил ссылку, тот видит отчёт. Ссылку можно отозвать.
4. Видео потребует хранилища и лимитов. Сейчас подходит только ссылка на файл или видеохостинг.

## Порядок работ

1. Ядро: конструктор с учётом истории, готовый к проведению план, цикл «план → факт → рекомендация» с принятием и отклонением, полнота карточки упражнения, цели игрока по видам и хронология.
2. Матч: выводы, задачи на тренировку, ручной видеоразбор по таймкодам.
3. Российский запуск: тарифы в конфигурации, статусы интеграций, Telegram (только при настроенном токене), журнал действий, согласия, тип команды.
4. Организации и роли: школа, тренеры, родители и игроки с проверкой прав на сервере, тесты изоляции.
